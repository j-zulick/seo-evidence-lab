# Release roadmap

The first release establishes a reproducible local product. Later releases add individually verifiable capabilities. Version labels below are proposed milestones, not created tags or promised delivery dates.

| Milestone | Deliverable | Acceptance evidence |
| --- | --- | --- |
| v0.1.0 local portfolio release | Existing local app, evidence walkthrough, scorecard, source history, docs and synthetic reports | Owner repository/license decisions, reviewed public files, actual remote fixture CI and exact release identity |
| v0.2 custom news bridge | Import an actual export from the separate SEO/LLM news agent and research/scraper, with source timestamps, hashes, deduplication and failure history | One real permitted observation moves through triage into a reviewed guidance version; affected findings retain source links and prior pins |
| v0.3 broader replay and retrieval | More deterministic criteria, expanded labeled queries, and dataset-aware local MCP reads | New rule regression cases and published benchmark comparison, including the existing paraphrase miss |
| Provider acceptance milestone | Authorized real Ahrefs/GSC/CrUX observations, genuine Jev evaluation and connected Langfuse tracing | Exact provider contracts, permitted scope/cost, matching observation windows and recorded real results |
| Community collection milestone | Approved bounded Reddit collection and retention/removal handling | Permitted access, removal/deletion tests, source corroboration and public-data minimization |
| Iteration 2 client operations | Scoped workspaces, authorization, ingestion jobs, budgets, monitoring and recovery | Real client pilot, access tests, recovery exercise, measured operating cost and explicit deployment approval |

## Release discipline

Publish actual verified changes in meaningful commits. Do not backdate work, manufacture activity, or rewrite the imported baseline to imply a longer public history. Tag a tested commit and update release notes when the scope changes. CI badges must reflect actual remote runs.

Keep live collection, hosted writes, schedules, model calls, and provider budgets disabled until separately authorized. Publishing the local source does not authorize a dynamic deployment. The existing protected static preview remains its own reviewed artifact.

## Success measures to establish later

Measure source-to-review delay, duplicate-story handling, retrieval coverage on an expanded labeled set, independent reviewer agreement, and actual client task outcomes. Do not replace these with synthetic six-case scores or claim improvements before measurements exist.
